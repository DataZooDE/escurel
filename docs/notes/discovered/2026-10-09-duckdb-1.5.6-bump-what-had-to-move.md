# DuckDB 1.5.5 → 1.5.6: everything that had to move together

**Symptom.** The engine bump itself was two lines (`Cargo.lock`: `duckdb` / `libduckdb-sys 1.10506.0`),
but the first demo on the new build still ran 1.5.5, the optimizer extension refused to load, and the
image build failed on a missing `gdrive`. Each had a different cause; none was a code bug.

**What moves with the pin.**
1. `Cargo.lock` (`libduckdb-sys` `1.<major><minor><patch>` packed: `1.10506.0` = 1.5.6). The precompiled
   `libduckdb` download in `.cargo/config.toml` follows it.
2. `Dockerfile`: `ARG DUCKDB_VERSION=v1.5.6` (asserted against `libduckdb-sys` at build time), the
   `extensions` stage (every baked extension is fetched for THAT version), the conditional `gdrive` bake.
3. Every locally built extension is version-locked: `anofox_optimize` and `gdrive` were rebuilt for
   1.5.6 (DuckDB submodule at the `v1.5.6` tag, `extension-ci-tools` on its `v1.5-variegata` branch,
   `make release`, footer checked with `duckdb -unsigned -c "LOAD …"`). Tests that load a local
   extension skip with a clear message on a version mismatch
   (`crates/escurel-index/tests/anofox_inventory_extension.rs`).
4. Anything that hand-picks a `libduckdb.so` must pick by version
   (`editors/vscode/demo/run.sh`, see the stale-libduckdb note of the same day).
5. The hetzner lab image stays on its own pin until rebuilt; a demo on a newer DuckDB diverges from
   lab until then.

**How to recognise a half-done bump.** `escurel-server --version` / the gateway log says the new
version but a `LOAD` fails with a version message; the image build's assertion lists a missing
extension; a consumer's `sql_view` over an extension-backed source errors on first use.

**Checklist for the next bump.** Bump `Cargo.lock`; grep for the old version string across
`Dockerfile`, `.cargo/config.toml`, `deploy/`, `docs/`, `editors/vscode/demo`; check the mirror has
every DataZoo extension for the new version; rebuild the local extensions; run the full workspace tests,
the live-postgres suites and the image build; refresh the demo and compare `gateway_duckdb_version()`.
