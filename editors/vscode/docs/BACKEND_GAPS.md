# Backend gaps the extension needs (kept next to SPEC.md)

Each entry names the tool/field the extension needs, why, and how the
extension degrades until it lands. Numbering continues SPEC §7.

| #    | Need                                                                                                                                                                                     | Why                                                                                                                                                                           | Status / degradation                                                                                                                                       |
| ---- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| PR-0 | `expand { raw: true }` → `content` (the stored markdown verbatim)                                                                                                                        | The skill editor must show and re-save the author's own text; `expand` only returned a parsed frontmatter object + body, so a save would rewrite YAML formatting and comments | **Landed** (gateway PR, skill 0.6.75). The FS provider reads `content`; on an older gateway it falls back to reassembling frontmatter + body and logs once |
| PR-1 | Live personal drafts (SPEC §7) | Instance editing in page-as-UI | **Landed** as `open_session { draft_id }`: a session on one of your own open drafts edits the held bytes, `close_session {commit: true}` saves them back to the draft, and the page moves only on promotion. Personal — only the author may open, apply ops to, or discard it. The extension still needs a Loro op path before editing can be turned on |
| PR-2 | `actions: [{skill, label?, mode?}]`                                                                                                                                                      | Contextual Skill-button labels                                                                                                                                                | Open. | PR-3 | Review-comment events for non-admins, page-ACL filtered | Review comments (M2) | **Landed** as the reserved `escurel:review-comment` carve-out (#591): a plain `review-comment` label names no skill, so a runner dispatched it and dead-lettered it. The gateway authorises the comment by the draft's visibility and files it on the draft's target page |

Notes on the wire that differ from SPEC wording:

- `session_cap_reached` is not a WS frame: it is HTTP `429 {error: "session_cap_reached"}` on the `/ws` upgrade (and a JSON-RPC `error.data.code` on `/mcp`). The WS client surfaces it as the non-blocking warning SPEC §1 asks for.
- `permission_denied` does not exist as a code; the gateway answers `forbidden` (payload `issues[].code` or `error.data.code`) and `admin_required`.
- `base_moved` is a boolean on `diff_draft`'s result, not an error code.
