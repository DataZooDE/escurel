Notes on the wire that differ from SPEC wording:

- `session_cap_reached` is not a WS frame: it is HTTP `429 {error: "session_cap_reached"}` on the `/ws` upgrade (and a JSON-RPC `error.data.code` on `/mcp`). The WS client surfaces it as the non-blocking warning SPEC §1 asks for.
- `permission_denied` does not exist as a code; the gateway answers `forbidden` (payload `issues[].code` or `error.data.code`) and `admin_required`.
- `base_moved` is a boolean on `diff_draft`'s result, not an error code.
